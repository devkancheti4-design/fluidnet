The knowledge was there. The search wasn't.

fluidnet repairs bug shapes it was taught, and proves each fix with your own test suite. On a real repository, what it lacked was where to look. buggy answers where — and fluidnet only lets that help through if its own certification passes.

Against an AI agent · same ten bugs, same machine

The agent was faster, and got all ten.

A frontier model working as a coding agent, one bug at a time, each on its own history-free copy of click, no network, no other copy of click — told only how to run the suite. Scored exactly as fluidnet was: byte-exact against click's code, the full suite, tests untouched.

Where the agent won

+

Speed: it reads the traceback and goes to the line. fluidnet spends about four minutes locating, then proves the fix unique — on these bugs, roughly seven times longer.

median 51 s vs 367 s
+

Judgement where the suite has none. On the two bugs fluidnet refused, two different fixes pass all 2,240 tests; the agent chose the right one by reading the code — a string cannot be subtracted, and the neighbouring method already had the correct check.

Where fluidnet still stands

+

No model and no tokens: about 50,000 tokens a bug for the agent, none for fluidnet, which runs offline and gives the same answer every time.

506,431 tokens vs 0
+

Every fix it ships is the only one its search found that passes. On those same two bugs a wrong fix also passes the suite — the agent was right, but nothing checked that it was. fluidnet says so instead of guessing.

0 wrong · refusals name both fixes
−

These bugs are one token wide in a well-tested library — the easiest regime for an agent, and the one where fluidnet's proofs cost the most time for the least visible gain.

one run each · not a benchmark of harder bugs

Does the novel become known? Replayed in commit order, 38% of 565 real fixes from click, arrow, rich and sortedcontainers repeat a pattern already seen in the same repository — 31% early in a project's life, 43% late — counting only ten pattern families; the rest fit none of those ten, which is a limit of the list, not proof they are new. A repeating pattern is still not a fix: that step is what the two panels above measure.

Not done yet

What this page does not know yet.

A deciding input for ambiguous fixes

When two fixes both pass, fluidnet should find the input where they differ and show both outputs, so a person picks in seconds. Not built yet.

buggy's missing operator

buggy cannot mutate -= / +=, so it could only propose deleting the line. Reported to buggy's owner, who confirmed it.

Harder bugs

Every bug here is one token wide. Multi-line and novel bugs — where an agent's judgement matters most — are not measured on this page.
