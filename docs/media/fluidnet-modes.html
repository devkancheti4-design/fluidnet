Which one, when

Pick by what is scarce.

Time is scarce

A red build blocking a release: run speed. The agent's reading gets the core to the line in seconds; the core still proves every fix.

Tokens are scarce

Overnight, CI, many repositories: run token-saving. Most bugs cost nothing; the agent is paid only for the facts the core cannot measure.

Neither changes the proof

Both modes ship only a fix that is certified on the full suite and the only passing program at its lines. Both refuse rather than guess.

Lean agent calls, not yet measured

A request carries only the facts — a median ~450 tokens. Real per-call usage awaits the Claude Code CLI on this machine, which reports "Credit balance is too low".
